# Pull Request Guidelines

> **目的**：チーム全体で統一された PR 作成ルールを定義し、レビュー効率と変更履歴の明瞭化を図る。
> **スコープ**：PR タイトル、本文構成、テンプレート、マージ方針など。

---

## PR の基本方針

- 1 PR = 1 機能（1 Issue）
- 小さく、明確に。500 行を超える変更は分割を検討する。
- 原則 1 名以上の Approve を必須とする。
- PR 作成時に自動実行されるテスト・Lint を確認してから提出する。
- 早期共有のため、ブランチを作成し作業を開始した時点で`Draft PR`を作成する。

---

## PR テンプレート運用

- `.github/PR_TEMPLATE/PULL_REQUEST_TEMPLATE.md` を使用

---

## PR タイトルルール

- コミットメッセージと同じく Conventional Commits を推奨とする。
  - 形式：`<type>(<scope>): <subject>`
- 日本語を使用する。「〜を追加」「〜を修正」など、文末は体言止めで統一する。
- WIP (作業中) の場合は `[WIP]` プレフィックスを付ける。
