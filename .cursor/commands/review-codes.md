# コードレビュー

## 概要

コードレビューを実施する。
次の手順に従って作業を進め、不明点があればユーザーへ質問する。
作業後にチェックリストを参照し、すべての項目が完了していることを確認する。

## 手順

### 1. 変更内容を確認
- 対象のブランチをチェックアウトする
- 変更差分を確認する

```bash
git fetch origin
git checkout <branch-name>
git diff origin/develop...HEAD
```

### 2. ローカルで動作確認
- 依存関係をインストールする
- プロジェクトのRulesで定義されている品質チェックツールを実行する
  - フォーマットチェック
  - リンターチェック
  - 型チェック
  - テスト実行

> **参考**: 各言語の品質チェック方法は以下を参照
> - バックエンド: `.cursor/rules/coding-rules/01-backend/03-python-quality-check.mdc`

### 3. チェックリストでレビュー
- 以下のチェックリストを使用して各項目を確認する
- 問題があれば指摘事項としてメモする

### 4. レビューコメントを作成
- コメント種類を使い分ける
  - **Must**: 必ず修正が必要
  - **Should**: 修正を推奨
  - **Nit**: 些細な指摘（任意）
  - **Question**: 質問や確認
- 具体的な修正案を含める
- なぜその変更が必要かを説明する

### 5. レビュー結果をまとめる
- レビュー結果を整理する
  - 修正が必要な箇所（Must/Should/Nit）
  - 質問事項（Question）
  - 良い実装箇所
- 改善提案を具体的にまとめる

## チェックリスト

### 機能性
- [ ] すべての要件が実装されている
- [ ] エラーハンドリングが適切
- [ ] 入力値のバリデーションが実装されている

### コード品質
- [ ] プロジェクトのコーディングルールに従っている
- [ ] 適切な命名規則に従っている
- [ ] ドキュメントコメントが日本語で記載されている
- [ ] 適切なレイヤーに配置されている

### テスト
- [ ] ユニットテストが追加されている
- [ ] 正常系・異常系・境界値のテストがある
- [ ] カバレッジが十分（目安: 85%以上）

### セキュリティ
- [ ] すべての入力が検証されている
- [ ] センシティブな情報がログに出力されていない
