# Create test scenario

## Overview

- このコマンドは、**プロダクトバックログアイテム（PBI）の情報をもとに BDD 形式のテストシナリオを作成する**ワークフローです。
- 作成されたテストシナリオは、受け入れ条件に基づいて機能の期待される動作を明確化し、実装ガイドとしても機能します。

## Rules

- テストシナリオは `.cursor/rules/test-scenario-guidelines.mdc` のガイドラインに従って作成すること。
- 受け入れ条件ごとに 1 つ以上のシナリオを作成すること。
- テストシナリオをファイル出力する際は、`.feature` 拡張子で出力すること。
- ファイル名は英小文字のスネークケース（単語間はハイフン `-` で区切る）で記載し、シナリオの主題や機能を端的に表すこと。（例: `explain-active-file.feature`, `code-block-actions.feature`）。
- テストシナリオの出力先ディレクトリは `histories/{今日の日付}/{PBIタイトル}/tests/` とし、存在しない場合は新規作成すること。
  - **今日の日付**: `date +%Y%m%d` コマンドの出力値を使用する。
- 既に同じファイル名が存在する場合は、内容を確認し、必要に応じて上書きするか、新しいファイル名を提案する。

## Steps

1. ユーザーからプロダクトバックログの「タイトル」「ユーザーストーリー」「受け入れ条件」を受け取る。受け取りが完了してから、次のステップに進む。
   - 受け入れ条件が複数ある場合は、すべて確認し、それぞれに対応するテストシナリオを作成する。
2. 受け取った情報をもとに、PBI で実装する機能のテストシナリオを作成する。
   - **受け入れ条件ごとに 1 つ以上のシナリオを作成し、すべての受け入れ条件がテスト可能な形でカバーされていることを確認する**。
   - `.cursor/rules/test-scenario-guidelines.mdc` のガイドラインに従って、BDD 形式（Gherkin 記法）で記述する。
3. テストシナリオを`.feature` 拡張子でファイル出力する（出力先やフォーマットルールは、**Rules** のルールを適用する）。
4. 作成したテストシナリオが `.cursor/rules/test-scenario-guidelines.mdc` に記載されている観点（独立性、ユーザー視点、具体的な値など）を満たしているか確認する。
