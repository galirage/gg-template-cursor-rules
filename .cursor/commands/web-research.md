# Web 調査レポート作成

## 概要

MCP ツールを網羅的に活用して Web 調査を行い、`/docs`ディレクトリにレポートを作成する。  
次の手順に従って作業を進め、不明点があればユーザーへ質問する。  
作業後にチェックリストを参照し、すべての項目が完了していることを確認する。

## 使用する MCP ツール

調査では以下の MCP ツールを**組み合わせて**使用し、情報を網羅的に収集する:

### 1. Brave Search (`mcp_brave-search_brave_web_search`)

- **用途**: 広範な Web 検索、最新情報の取得
- **特徴**: ニュース、記事、公式ドキュメントを素早く検索
- **使い方**: `query`パラメータに検索キーワードを指定

### 2. Perplexity (`mcp_perplexity-ask_perplexity_ask`)

- **用途**: 深い質問回答、情報の統合・要約
- **特徴**: 複数ソースを統合した質の高い回答
- **使い方**: `messages`配列で会話形式の質問を送信

### 3. Browser（@Browser / Playwright MCP）

- **用途**: 実際の Web ページ閲覧、動的コンテンツの取得
- **特徴**: スクリーンショット取得、DOM 解析
- **主要ツール**:
  - `browser_navigate`: URL に移動
  - `browser_snapshot`: ページのアクセシビリティスナップショット取得
  - `browser_take_screenshot`: スクリーンショット取得
  - `browser_click`, `browser_type`: ページ操作

### 4. GitHub MCP (`mcp_github_*`)

- **用途**: リポジトリ検索、コード検索、イシュー調査
- **特徴**: 実装例、ベストプラクティスの発見
- **主要ツール**:
  - `search_repositories`: リポジトリ検索
  - `search_code`: コード検索
  - `get_file_contents`: ファイル内容取得

## 手順

### 1. 調査テーマの確認

- ユーザーから調査テーマを受け取る
- 不明点があれば質問する
- 調査の深さ（概要/詳細）を確認する

### 2. 多角的な情報収集

#### Step 2.1: Brave Search で広範な検索

```
調査対象の概要、最新トレンド、関連キーワードを取得
- 公式ドキュメントのURL
- 技術ブログ記事
- ベストプラクティス記事
```

#### Step 2.2: Perplexity で深堀り質問

```
Brave Searchの結果を踏まえ、より具体的な質問を行う
- 実装パターンの比較
- メリット・デメリット
- 注意点・落とし穴
```

#### Step 2.3: Browser で公式ドキュメント確認

```
重要なページを実際に閲覧し、最新情報を確認
- 公式ドキュメントのスクリーンショット取得
- コードサンプルの確認
- バージョン情報の確認
```

#### Step 2.4: GitHub で実装例を調査

```
実際のプロジェクトでの使用例を検索
- 人気リポジトリでの実装パターン
- イシューやディスカッションでの議論
```

### 3. 情報の整理・統合

- 各ソースからの情報を統合
- 矛盾する情報がないか確認
- 信頼性の高い情報を優先

### 4. レポート作成

- `/docs/`ディレクトリに Markdown ファイルを作成
- ファイル名: `調査テーマを表す英語名.md`（例: `COSMOS_DB_PARTITION_DESIGN.md`）

### 5. レポート構成

```markdown
# {調査テーマ}

## 概要

{テーマの概要説明}

## 調査日時

{YYYY-MM-DD}

## 調査方法

使用した MCP ツール:

- Brave Search: {使用した検索クエリ}
- Perplexity: {質問内容}
- Browser: {閲覧した URL}
- GitHub: {検索したリポジトリ/コード}

## 調査結果

### 1. {トピック 1}

{詳細内容}

### 2. {トピック 2}

{詳細内容}

## ベストプラクティス

- {ベストプラクティス 1}
- {ベストプラクティス 2}

## 注意点・落とし穴

- {注意点 1}
- {注意点 2}

## このプロジェクトへの適用

{mu-logging-function プロジェクトへの具体的な適用方法}

## 参考リンク

- [{タイトル 1}]({URL1})
- [{タイトル 2}]({URL2})

## 関連ドキュメント

- {プロジェクト内の関連ドキュメントへのリンク}
```
