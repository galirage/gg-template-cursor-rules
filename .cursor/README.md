## Usage

- **チーム単位での運用** を前提とします。
- プロジェクトの進行や開発体制の変化に応じて、**定期的な見直し・アップデート**を行ってください。
- ルールの内容は具体例を記述し、曖昧な表現は避けてください。
- **注意事項**:  
  他の Rules 定義方法（User Rules、`AGENTS.md`、`.cursorrules` など）を併用する場合は、**優先順位の競合**にご注意ください。

## 推奨する運用方針

- **プロジェクト固有ルール**
  - `.cursor/index.mdc` にて、プロジェクト全体の共通コンテキストを定義する。
  - 例：命名規則、フォルダ構成、ドキュメント構成指針など
- **動的コンテキストルール**
  - 必要なタイミングでのみ読み込まれるため、柔軟な適用が可能
  - `.cursor/rules/*.mdc` にて、タスクやコンテキストごとに適用されるルールを定義する。
  - 例：ユニットテスト、UI コンポーネント設計、API 設計など
