# Cursor Rulesテンプレート

## 概要

このリポジトリは、Cursorを使ったAI駆動開発において、
**AIエージェントがプロジェクトの設計思想を理解し、一貫性のある高品質なコードを生成できるようにする**ためのRulesテンプレートです。

> **注意** 
> 現在、FastAPIによるバックエンドのみを対象に実装しています。
> この後の追加予定については「今後の追加予定」をご確認ください。

## 前提条件

このRulesファイルが前提としているプロジェクト構成は、モノレポジトリ構成であり、下記の技術要素の採用を前提としています。

|  | 言語 | フレームワーク | ソフトウェアアーキテクチャ |
| --- | --- | --- | --- |
| バックエンド | Python | FastAPI | オニオンアーキテクチャ |

| 技術 | バージョン | 用途 | 公式URL |
| --- | --- | --- | --- |
| Python | 3.12–3.13 | プログラミング言語 | https://www.python.org/downloads/ |
| uv | ~=0.8.0 | パッケージマネージャー | https://docs.astral.sh/uv/ |
| FastAPI | ~=0.118.0 | Web フレームワーク | https://fastapi.tiangolo.com/ |
| Pydantic | ~=2.11.0 | データバリデーション | https://docs.pydantic.dev/ |
| pytest | ~=8.4.0 | テストフレームワーク | https://docs.pytest.org/ |
| httpx | ~=0.28.0 | HTTP クライアント | https://www.python-httpx.org/ |
| pytest-cov | ~=7.0.0 | カバレッジの測定 | https://pytest-cov.readthedocs.io/en/latest/ |
| pyright | ~=1.1.0 | 静的型チェッカー | https://microsoft.github.io/pyright/ |
| ruff | ~=0.13.0 | リンター/フォーマッター | https://docs.astral.sh/ruff/ |


## 定義していること・定義していないこと

### 定義していること

#### コーディング規約
- Python/FastAPIでの命名規則、コメント、設計原則等のコーディングスタイル
- リンター・フォーマッター・型チェッカー（ruff、pyright）を活用した品質チェックルール

#### バックエンド実装
- オニオンアーキテクチャに基づいた各層（ドメイン、インフラストラクチャ、プレゼンテーション、ユースケース）の実装ルール
  - ドメイン層のエンティティ、バリューオブジェクト、リポジトリインターフェースの実装ルール
  - インフラストラクチャ層のリポジトリ実装ルール
  - プレゼンテーション層のルーター、Pydanticスキーマの実装ルール
  - ユースケース層のビジネスロジックの実装ルール

#### テストの実装
- 単体テスト、契約テストの実装ルール

#### ワークフロー
- Conventional Commitsに準拠したGitコミットメッセージの記述ルール

### 定義していないこと

- フロントエンド開発のルール（今後追加予定）
- 採用するDB・ORMに合わせた設計ルール
- 採用するインフラサービスに合わせたデプロイ方法
- パフォーマンスを考慮した設計ルール


## 適用方法

### 1. リポジトリをクローンまたはダウンロード

```bash
git clone https://github.com/galirage/gg-template-cursor-rules.git
```

### 2. `.cursor/rules/` ディレクトリを自身のプロジェクトにコピー

```bash
cp -r gg-template-cursor-rules/.cursor/rules/ your-project/.cursor/
```

### 3. Cursorエディタでプロジェクトを開く

Cursorエディタでプロジェクトを開くと、自動的に`.cursor/rules/`配下のルールファイルが**Project Rules**として読み込まれます。

## 各Rulesの概要

### 基本コーディングルール（`coding-rules/00-common/`）

#### `00-common-rules.mdc`

- **概要**
  - プロジェクト全体で共通する設計原則、命名規則、品質基準、コメントスタイルを定義します。
- **効果**
  - AIエージェントがプロジェクトのディレクトリ構成、命名規則、品質チェック項目、コメント記述ルールを理解し、一貫性のあるコードを生成できるようになります。
- **カスタマイズポイント**
  - プロジェクト固有の命名規則（ドメイン用語、業界特有の概念）をプロジェクトに合わせて調整してください。

### バックエンドコーディングルール（`coding-rules/01-backend/`）

#### `00-tech-stack.mdc`

- **概要**
  - バックエンド開発で使用する技術スタックを定義します。
- **効果**
  - AIエージェントがプロジェクトの技術スタックを理解し、適切なライブラリとAPIを使用したコードを生成できるようになります。
- **カスタマイズポイント**
  - 使用する技術スタック（フレームワーク、DB）をプロジェクトに合わせて調整してください。

#### `01-software-architecture.mdc`

- **概要**
  - バックエンド開発で採用するソフトウェアアーキテクチャと詳細なディレクトリ構成を定義します。
- **効果**
  - AIエージェントがソフトウェアアーキテクチャを理解し、適切な層にファイルを配置し、依存関係を守ったコードを生成できるようになります。
- **カスタマイズポイント**
  - ソフトウェアアーキテクチャやディレクトリ構成をプロジェクトに合わせて調整してください。

#### `02-setup.mdc`

- **概要**
  - バックエンド開発環境のセットアップ手順を定義します。
- **効果**
  - AIエージェントが開発環境のセットアップ方法を理解できるようになります。
- **カスタマイズポイント**
  - 開発環境の構築手順（Docker、DevContainer）をプロジェクトに合わせて調整してください。

#### `03-python-quality-check.mdc`

- **概要**
  - Pythonコードの品質チェックツール（ruff、pyright、pytest）と実行手順を定義します。
- **効果**
  - AIエージェントが品質基準を満たすコードを生成し、適切なコマンドで品質チェックを実行できるようになります。
- **参照**
  - `app/backend/ruff.toml` - Ruff設定ファイルの参照実装
- **カスタマイズポイント**
  - 品質ツールの選定やカバレッジ閾値の設定をプロジェクトに合わせて調整してください。

#### `04-python-coding-style.mdc`

- **概要**
  - Python固有のコーディングスタイル（命名規則、型ヒント、docstring）を定義します。
- **効果**
  - AIエージェントがPython固有のコーディング規約を理解し、一貫したPythonコードを生成できるようになります。
- **カスタマイズポイント**
  - プロジェクトに合わせてコーディングスタイルを調整してください。

#### `05-00-domain-implementation.mdc`

- **概要**
  - ドメイン層の実装ルール（エンティティ、値オブジェクト、リポジトリインタフェース）を定義します。
- **効果**
  - ドメイン層の設計ルールに基づいたコードを生成できるようになります。
- **カスタマイズポイント**
  - ソフトウェアアーキテクチャやディレクトリ構成をプロジェクトに合わせて調整してください。

#### `05-01-infrastructure-implementation.mdc`

- **概要**
  - インフラ層の実装ルール（リポジトリ実装）を定義します。
- **効果**
  - インフラ層の設計ルールに基づいたコードを生成できるようになります。
- **カスタマイズポイント**
  - ソフトウェアアーキテクチャやディレクトリ構成をプロジェクトに合わせて調整してください。
  - 採用するDBやORM（Piccolo、SQLAlchemy等）をプロジェクトに合わせて調整してください。

#### `05-02-presentation-implementation.mdc`

- **概要**
  - プレゼンテーション層の実装ルール（FastAPIルーター、リクエスト/レスポンススキーマ）を定義します。
- **効果**
  - プレゼンテーション層の設計ルールに基づいたコードを生成できるようになります。
- **カスタマイズポイント**
  - ソフトウェアアーキテクチャやディレクトリ構成をプロジェクトに合わせて調整してください。


#### `05-03-usecase-implementation.mdc`

- **概要**
  - ユースケース層（アプリケーション層）の実装ルールを定義します。
- **効果**
  - AIエージェントがユースケース層の設計ルールに基づいたコードを生成できるようになります。
- **カスタマイズポイント**
  - ソフトウェアアーキテクチャやディレクトリ構成をプロジェクトに合わせて調整してください。


#### `05-04-test-code-implementation.mdc`

- **概要**
  - テスト戦略と実装ルールを定義します。
- **効果**
  - AIエージェントがテスト戦略を理解し、適切なテストケースとテストコードを生成できるようになります。
- **カスタマイズポイント**
  - テスト戦略（カバレッジ目標、テストツール、テスト対象範囲）をプロジェクトに合わせて調整してください。

#### `06-error-handling.mdc`

- **概要**
  - エラーハンドリングと例外処理の実装パターンを定義します。
- **効果**
  - AIエージェントがエラーハンドリング方針を理解し、一貫したエラー処理を含むコードを生成できるようになります。
- **カスタマイズポイント**
  - エラー分類方法（エラー種別、エラーコード体系）をプロジェクトに合わせて調整してください。

#### `07-logging-guidelines.mdc`

- **概要**
  - 構造化ログの実装方針とログレベルの使い分けを定義します。
- **効果**
  - AIエージェントがログ実装方針を理解し、一貫したログ出力コードを生成できるようになります。
- **参照実装**
  - `app/backend/src/log/logger.py` - 構造化ログ（structlog + Cloud Logging対応）の参照実装
- **カスタマイズポイント**
  - ログライブラリ（structlog、loguru）やログ出力形式をプロジェクトに合わせて調整してください。

### ワークフロールール（`workflow-rules/`）

#### `git-commit-rule.mdc`

- **概要**
  - Gitコミットメッセージのルール（Conventional Commits）を定義します。
- **効果**
  - AIエージェントがプロジェクトのコミットメッセージルールを理解し、適切なコミットメッセージを提案できるようになります。
- **カスタマイズポイント**
  - typeの種類やscopeの定義、コミットメッセージの言語（日本語/英語）をプロジェクトに合わせて調整してください。
